# Boas Práticas

Revisitar itens `DIRECIONAL_LONGO_PRAZO` a cada revisão periódica para verificar se algum já
amadureceu o suficiente para ser reclassificado como `COMPROMETIDO_CURTO_PRAZO` com data real —
a transição entre os dois estados deveria ser uma decisão consciente, não automática por
passagem de tempo.

Manter a seção de itens fora de escopo tão visível quanto a de itens priorizados — a decisão de
não fazer algo é informação tão valiosa quanto a decisão de fazer, especialmente para quem
pergunta "por que vocês não estão trabalhando em X".

Nomear a autoridade específica (pessoa ou papel), não apenas "liderança" de forma genérica, ao
sinalizar decisão que exige aprovação externa — quanto mais específico, mais fácil de fato buscar
a decisão em vez de deixá-la pendente indefinidamente.

Comparar o padrão de motivo de atraso entre revisões sucessivas, não apenas revisão isolada — um
motivo que se repete revela um problema sistemático que uma única revisão não teria capturado
sozinha.


Registrar a data da última revisão de forma visível no próprio roadmap, não apenas no histórico
interno — quem consulta o documento deveria conseguir avaliar rapidamente se está olhando para
algo recém-atualizado ou para uma versão que já pode estar desatualizada há meses.

Essa visibilidade simples reduz drasticamente a chance de alguém tomar decisão baseada numa versão do roadmap que já não representa mais a realidade atual do projeto.
