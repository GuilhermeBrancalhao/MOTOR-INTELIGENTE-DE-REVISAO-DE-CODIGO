# Introdução

Documentação desatualizada é pior do que ausência de documentação — quem lê um documento
desatualizado confia nele exatamente como confiaria num atual, e a confiança traída custa mais
caro do que a ausência de informação, que ao menos sinaliza a necessidade de investigar. Este
volume trata de governança de documentação para um sistema com componente de IA: como uma decisão
arquitetural com consequência duradoura é registrada, como esse registro nunca é apagado ao mudar
de ideia, como documentação vive junto do código que descreve, como sua vigência é verificada
explicitamente, e como conteúdo gerado automaticamente nunca é editado manualmente por engano.

A decisão arquitetural registrada — o ADR — é o núcleo deste volume. Uma decisão tomada sem
registro do contexto que a motivou é uma decisão que, revisitada meses depois, parece arbitrária
mesmo quando não era. O contexto é o que permite julgar, no futuro, se a razão original ainda se
sustenta ou se as circunstâncias mudaram o suficiente para justificar revisão.

Este próprio acervo é, ele mesmo, um exemplo do princípio que este volume defende: cada volume
registra não apenas o que decidir, mas por que — e as seções de Roadmap e Referências Cruzadas
existem justamente para que uma decisão de escopo, quando revisitada, tenha o contexto original
disponível, não precise ser reconstruída de memória.
