# Conclusão

Documentação que não é mantida com o mesmo rigor que se espera do código que ela descreve tende a
se tornar, com o tempo, uma fonte de desinformação ativa em vez de uma fonte de conhecimento. As
seis regras deste volume tratam documentação como um artefato que exige disciplina equivalente:
decisão registrada com contexto imutável, versionamento junto do código, vigência verificada, e
separação clara entre o que é gerado e o que é mantido manualmente.

A regra mais fácil de negligenciar é W4 — verificação explícita de vigência. É tentador assumir
que documentação escrita corretamente uma vez permanece correta, mas código muda constantemente, e
sem verificação ativa, a distância entre o que o documento afirma e o que o sistema realmente faz
cresce silenciosamente até alguém confiar nela e ser enganado.

A analogia mais direta é com o próprio código: ninguém aceitaria reescrever o histórico de commits
para "corrigir" uma decisão passada — o mesmo padrão de preservar história, mesmo quando a decisão
mudou, vale para documentação de arquitetura. As seis regras deste volume garantem que
documentação receba esse mesmo respeito por sua própria história.
