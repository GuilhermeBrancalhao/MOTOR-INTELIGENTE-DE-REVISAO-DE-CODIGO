# Boas Práticas

Revisar itens de dívida técnica registrada periodicamente, não apenas no momento em que são
criados — um item adiado por um motivo específico pode deixar de fazer sentido conforme o sistema
evolui, e a revisão periódica é o que capturaria essa mudança.

Investigar regressão (H5) mesmo quando o indicador continua acima do limiar de gate — uma queda
que ainda passa no gate hoje pode ser o início de uma tendência que eventualmente vai falhar.

Tratar exceção de gate concedida repetidamente para o mesmo tipo de mudança como sinal de que o
limiar, ou o processo que produz aquele tipo de mudança, precisa de revisão — não apenas conceder
a mesma exceção indefinidamente.

Expor as submétricas nomeadas (H6) no mesmo lugar que o indicador agregado, não escondidas atrás
dele — quem consome o indicador deveria conseguir decompor a origem de uma queda sem precisar
caçar dados em outro lugar.


Registrar, junto de cada dívida técnica, uma data de revisão sugerida, não apenas a data de
criação — isso transforma a revisão periódica de uma boa intenção vaga numa ação com prazo
esperado, mais fácil de cobrar depois.

Mesmo uma data aproximada, revisada e ajustada depois, é melhor do que nenhuma expectativa temporal declarada desde o registro inicial da dívida.
